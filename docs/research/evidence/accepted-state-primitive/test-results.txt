PROOF-BY-PROOF OUTCOMES
-----------------------

[PASS] ONE-WINNER EXPECTED-BASE COMMIT
    S01OneWinnerCommitTest.singleWinnerPerExpectedBase
    250 rounds x 8 concurrent writers, all presenting the SAME expected base,
    released through a CyclicBarrier.
    Asserted and observed per round:
        exactly 1  APPLIED
        exactly 7  STALE
        acceptedSequence advanced by exactly +1
        surviving policy == the winner's candidate
        runtimeInstanceId carried forward unchanged
    Aggregate: 2000 commit attempts, 250 accepted commits, final sequence == 250.
    Candidate constructions == 2000 == one per attempt, so the store never
    rebuilt any candidate.

[PASS] NO INTERNAL RETRY / NO REBASE
    Structural: the store's commit() accepts an already-built candidate, not a
    builder function, so there is nothing the store could re-invoke. Proven by
    S01ApiMisuseTest.storeSurfaceIsTwoOperations (surface == {commit, current}).
    Behavioural: sequence advances +1 per round for 8 attempts
    (S01OneWinnerCommitTest). Under internal retry it would advance +8.
    Contrast: S01VersionedStateHolderContrastTest.staleCallerIsRebasedAndOverwritesWinner
    shows the current generic primitive invokes its builder twice, is handed
    bases [0, 1], reports success to the stale caller, and lets that caller
    overwrite the winner.

[PASS] RUNTIME-INSTANCE MISMATCH
    S01ExpectedBaseMismatchTest.runtimeInstanceMismatchIsStale
    expected runtimeInstanceId != actual -> STALE
    accepted envelope identical BY REFERENCE afterwards (no CAS occurred)
    acceptedSequence unchanged, policy unchanged.

[PASS] ACCEPTED-SEQUENCE MISMATCH
    S01ExpectedBaseMismatchTest.sequenceMismatchIsStale  (base behind actual)
    S01ExpectedBaseMismatchTest.futureSequenceIsStale    (base ahead of actual)
    Both -> STALE, accepted envelope identical by reference, sequence unchanged.
    S01ExpectedBaseMismatchTest.matchingBaseIsApplied confirms the positive case
    installs a NEW envelope instance, which is what makes reference identity a

[PASS] UNCHANGED BOUNDARY
    S01UnchangedBoundaryTest.identicalCandidateIsUnchangedWithoutCommit

REPEATABILITY
-------------
Because the one-winner, publication and rebase proofs are race-dependent, the
suite was re-run three additional times with forced task re-execution:

    .\gradlew.bat acceptedStatePrimitiveTest --rerun --no-daemon

RUN 1  BUILD SUCCESSFUL in 7s
RUN 2  BUILD SUCCESSFUL in 7s
RUN 3  BUILD SUCCESSFUL in 7s

Four executions in total, zero failures. The two proofs that would otherwise be
timing-sensitive are constructed to be deterministic rather than probabilistic:

  - the one-winner proof asserts sequence arithmetic (+1 per round), which holds
    regardless of which writer wins and regardless of scheduling;
  - the rebase proof uses a latch-controlled handoff that forces the interleaving
    rather than hoping for it.

The publication proof is the only genuinely probabilistic one. It is bounded by
20 000 commits against 6 concurrent readers per execution, so four executions
represent 80 000 commits observed without a single torn or partial read.
